## 🔴 HIGH Priority

### 1. Insecure CORS Configuration
**File:** `demetra/app.py:14–20`  
**Category:** `insecure_cors`

`allow_origins=["*"]` combined with `allow_credentials=True` is invalid per the CORS specification.
Browsers reject responses that return `Access-Control-Allow-Origin: *` alongside
`Access-Control-Allow-Credentials: true`, silently breaking credentialed requests. The wildcard also
allows any origin to read unauthenticated API responses.

**Fix:** Replace `"*"` with an explicit allowlist:
```python
allow_origins=["https://demetra.manti.by"]
```

### 2. Database Password Equals the Project Name
**File:** `demetra/services/project.py:88`  
**Category:** `weak_credentials`

```python
role_name = password = db_name = project_name
```

Every new project gets a PostgreSQL role whose password is identical to the role/database name —
a value derived from the public GitHub repository name + 8 hex chars. Anyone who knows the project
name can authenticate directly to that project's database.

**Fix:** Generate a cryptographically random password:
```python
import secrets
role_name = db_name = project_name
password = secrets.token_urlsafe(32)
```

### 3. DDL Statements Use SQLAlchemy Bound Parameters for Identifiers (Broken + Injection Risk)
**File:** `demetra/services/project.py:96–116`, `demetra/services/project.py:140–151`  
**Category:** `sql_injection` / `broken_query`

PostgreSQL DDL statements (`CREATE ROLE`, `GRANT`, `CREATE DATABASE`, `DROP DATABASE`, `DROP ROLE`)
do not accept bound parameters for identifiers. SQLAlchemy's `text()` substitutes `:role_name` as a
*string literal*, producing malformed SQL like `CREATE ROLE 'my_project' ...` which PostgreSQL
rejects. These queries are likely failing silently or raising errors.

Additionally, if the substitution were to work, identifiers would not be properly quoted — a project
name with SQL metacharacters could inject arbitrary DDL.

**Fix:** Use explicit identifier quoting after the already-existing validation:
```python
# project_name is already validated via regex + reserved-word check
from sqlalchemy import text

safe_role = connection.dialect.identifier_preparer.quote(role_name)
await connection.execute(
    text(f"CREATE ROLE {safe_role} WITH LOGIN PASSWORD :password CREATEDB"),
    {"password": password},
)
```

## 🟡 MEDIUM Priority

### 4. WebSocket Log Stream Has No Ownership Check (IDOR)
**File:** `demetra/api/watcher.py:19–40`  
**Category:** `idor` / `information_disclosure`

The `/ws/v1/watcher/logs` endpoint verifies only that the user is authenticated, but does not
check that the requested `task_id` belongs to that user. Any authenticated user can stream the
logs of any other user's session by supplying a known or guessed UUID.

Session logs contain full workflow output including code diffs, build plans, and potentially
secrets echoed by build tools.

Note: `DELETE /sessions/{task_id}` correctly passes `user_id` to `delete_session` — the same
pattern should be applied here.

**Fix:** Look up the session before streaming; close with 4003 if it doesn't belong to the user:
```python
session = await get_session(task_id)
if not session or session["user_id"] != user.id:
    await websocket.close(code=4003, reason="Forbidden")
    return
```

### 5. MCP `auth_token` Parameter Is Defined but Never Enforced
**File:** `demetra/tools/database.py:192–280`  
**Category:** `authentication_bypass`

All four MCP tools advertise an optional `auth_token` parameter, but `_call_tool` never reads
or validates it. Any process that can reach the MCP server can enumerate the full database schema
and read all data (minus sensitive column names) without credentials.

**Fix:** Either validate `auth_token` via the existing `get_current_user` auth service, or remove
the misleading parameter and explicitly document that the MCP server operates within a trusted
local process boundary.

### 6. OAuth Redirect URL Parameters Are Not URL-Encoded
**File:** `demetra/services/auth.py:32–33`  
**Category:** `oauth_security` / `functional_bug`

```python
query = "&".join(f"{k}={v}" for k, v in params.items())
```

Parameters are concatenated without `urllib.parse.urlencode`. The `scope` value
`"read:user user:email"` contains a space, producing an invalid URL. Any `redirect_uri` value
with query parameters or special characters will corrupt the URL.

**Fix:**
```python
from urllib.parse import urlencode
query = urlencode(params)
```

### 8. `LIMIT` / `OFFSET` Bound as Strings Instead of Integers
**File:** `demetra/tools/database.py:182–185`  
**Category:** `logic_bug`

```python
params.append(str(limit))   # should be int
params.append(str(offset))  # should be int
```

`asyncpg` receives text values `'100'` and `'0'` where PostgreSQL expects integers for
`LIMIT`/`OFFSET`. PostgreSQL usually casts these implicitly, but passing the wrong type is
incorrect and may fail on strict configurations.

**Fix:** Drop the `str()` wrappers — `limit` and `offset` are already integers at that point:
```python
params.append(limit)
params.append(offset)
```
