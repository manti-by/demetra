# MNT-188: Waitlist

## TL;DR

Blocked users can join a waitlist (HTTP 202) and admins approve entries via CLI to promote them to the allowlist. Implemented `waitlist_entries` table, waitlist service (`demetra/services/auth/waitlist.py`), auth-flow 202 handling, React waitlist UI, and CLI commands.

---

## Overview

Service in `demetra/services/auth/waitlist.py`: join/approve/list/remove, plus approval notification and audit. New `waitlist_entries` table via Alembic; auth flows updated to return 202 waitlist path; CLI commands and tests added.

## Build plan

### Key Design Decisions

1. **Table schema:** `waitlist_entries` with `id`, `entry_type` (email/github_username), `value` (normalized), `status` (pending/approved/rejected/joined), `note`, `created_at`, `approved_at`, `approved_by`, `joined_at`, `notified_at`; unique `(entry_type, value)`.
2. **Service module:** `demetra/services/auth/waitlist.py` for join/approve/list/remove.
3. **Auth integration:** 202 `waitlisted_response` in auth/github flows when allowlist blocks user.
